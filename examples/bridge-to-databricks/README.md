# Bridge a private SQL Server to Databricks through ADF

Offline example (PB-064 phase 5). The `sales` flow ingests two SQL Server tables
into Databricks history tables. Databricks cannot reach the source, so the
connection records `route: bridge`: ADF reads the source through its existing
linked service (and self-hosted integration runtime), a Databricks job verifies
and publishes each landed snapshot, and Lakeflow applies it to history.

```yaml
connections:
  erp:
    kind: sql-server
    route: bridge
    binding: erp_adf # ADF's native SQL Server binding
    bridge:
      provider: landing # the ADF configuration that lands the source
      publisher: publisher # the Databricks configuration that publishes deliveries
      landing:
        { linkedService: landing_adls, fileSystem: landing, path: retail }
      handover: files # the ADLS binding both platforms read
      publication: { credential: { ... }, maximumDropPercent: 50 }
```

The flow itself is an ordinary `snapshot-with-history@v1` flow with the
connection and one `source: {schema, table}` per table. Core expands it into
three flows, each generated by its own provider:

| Flow            | Provider configuration | Standard                   |
| --------------- | ---------------------- | -------------------------- |
| `sales_land`    | `landing` (ADF)        | `snapshot-land@v1`         |
| `sales_publish` | `publisher`            | `snapshot-publication@v1`  |
| `sales`         | `processing`           | `snapshot-with-history@v1` |

```sh
ingestron provider install adf@4.7.0
ingestron provider install databricks@3.7.0
ingestron check
ingestron build --delivery --out out
```

`check` reports one route for `sales`: _bridge: lands on landing, ingests on
processing via snapshot-land@v1 → snapshot-publication@v1 →
snapshot-with-history@v1_, with the ADF SQL Server reference record. `build`
writes three exports: the ADF Copy pipelines, the publication job with its
handover files, and the Lakeflow pipeline. The landing path, publication root
and delivery index agree across the three, and each history table checks the
dataset its publisher writes.

When a flow instead reads SQL Server natively on Databricks (Lakeflow Connect
query ingestion, billed separately) and ADF is configured, `check` lists this
bridge as the alternative. Nothing switches on its own; record `route: bridge`
to use it.

Generation is offline. Native execution needs the existing factory, linked
services, integration runtime, storage, workspace, secret scope and permissions
described in [the snapshot handover guide](../../docs/snapshot-handover.md).
